@AGENTS.md

## Project

Arcade Vault — a planned online arcade platform where users play games and compete on points (per README.md, in Spanish). The repo is currently an unmodified `create-next-app` scaffold: only `app/page.tsx`, `app/layout.tsx`, and `app/globals.css` exist, all still boilerplate. There is no data layer, routing beyond `/`, or game logic yet.

## Stack

- Next.js 16 (App Router only — no `pages/` directory), React 19, TypeScript (strict mode).
- Tailwind CSS v4 via `@tailwindcss/postcss` (no `tailwind.config.*`; theme tokens are defined inline in `app/globals.css` with `@theme inline`).
- Path alias `@/*` maps to the repo root (`tsconfig.json`).

## Commands

- `npm run dev` — start the dev server.
- `npm run build` — production build.
- `npm run start` — run the production build.
- `npm run lint` — ESLint via `eslint.config.mjs` (flat config, extends `eslint-config-next` core-web-vitals + typescript).
- No test runner is configured in this repo yet.

## Next.js 16 caveat

This project pins a Next.js version newer than most training data and has breaking API/convention changes (see `AGENTS.md`, which is regenerated by `next dev` — keep it committed rather than deleting it from diffs). Before writing App Router code, check the matching guide under `node_modules/next/dist/docs/01-app/` (getting-started, guides, api-reference) rather than relying on prior Next.js knowledge. For example, `app/layout.tsx` already uses the newer typed route props convention (`LayoutProps<"/">` from the generated `.next/types`) instead of a hand-written `{ children: React.ReactNode }` prop type.
